| 5 | 是否保存完整搜尋關鍵字 | 預設**不保存原文**，只記錄「有搜尋、結果數量、關鍵字長度」；系統設定可改為保存 | 使用者可能把密碼、個資當搜尋字串 | 請確認 |
| 6 | 任務管理、獨立知識庫等模組 | 第一版不做；專案容器設計已保留擴充空間 | 避免範圍擴大 | 請確認 |
| 7 | 專案刪除後的資料保留或回收 | 軟刪除；管理後台提供「回收區」可還原；永久刪除僅限最高權限管理者並需二次確認 | 防止誤刪；永久刪除屬破壞性操作 | 請確認回收區保存天數 |

## B. 分析規格時新發現、需要決定的項目

| # | 項目 | 建議 | 說明 |
|---|---|---|---|
| 8 | 編輯／刪除是否必須同時具備「查看」 | **必須**（兩層都要有查看） | 不能修改看不到的內容；見 04 文件 1.2 |
| 9 | 新增隨手記需要哪個權限 | 專案「編輯」（雙重授權） | 只有查看權限者唯讀 |
| 10 | 修改／刪除隨手記 | 作者本人：需「編輯」；他人的隨手記：需「刪除」權限才能刪除、不能修改 | 防止冒用他人名義修改內容；若希望編輯者可改任何人的隨手記請告知 |
| 11 | 隨手記修改是否保留歷史 | 第一版只記錄「誰在何時修改」到操作紀錄，不保存舊內容 | 規格只要求專案說明保留版本；隨手記可能含敏感資料，保存歷史會擴大外洩面 |
| 12 | 非管理者建立專案後，自己能否看到 | 建立者自動取得該專案「查看＋編輯」（不含刪除），仍受全域權限限制 | 否則建立完立刻看不到；規格 4.2 規定授權名單由管理者設定，此為唯一自動授權 |
| 13 | 建立時「設定授權使用者」由誰操作 | 僅最高權限管理者 | 與 4.2 一致 |
| 14 | 最高權限管理者是否只能有一位 | 資料結構支援多位，介面第一版限制只能一位 | 救援流程、操作責任較單純 |
| 15 | `can_manage_users` 的範圍 | 第一版只存欄位、不開放；管理後台僅限最高權限管理者 | 若開放，需規定「不可授予自己沒有的權限、不可管理最高權限管理者」 |
| 16 | 專案名稱、關鍵字是否需要編輯權限以外的限制 | 名稱修改同「編輯」；名稱不要求唯一 | 通用容器，不同部門可能有同名專案 |
| 17 | 離開專案時間 | 第一版不記錄 | 無法可靠取得；規格亦註明「若能可靠取得」 |
| 18 | 上午／下午的分界與時區 | 系統時區預設 `Asia/Taipei`，00:00–11:59 上午、12:00–23:59 下午 | 可於系統設定調整 |
| 19 | 「兩者皆遺失」救援的強度 | 加冷卻時間（預設 30 分鐘）並寄送通知 | 此情境只有 Email 一個因素，風險最高 |
| 20 | 本 Repo 的位置 | 目前放在 `jeepay` repo 的 `project-hub/` 子目錄 | `jeepay` 是 Java 支付系統，與本平台無關。建議日後移到獨立的 Git Repo，避免 CI、授權條款與發佈流程互相干擾 |
| 21 | 免費主機存放內部敏感資料 | 正式導入前評估付費主機，或至少建立定期匯出備份 | 免費主機無 SLA 與備份保證 |
| 22 | 地區用語轉換（如「記憶體／内存」） | 第一版只做字形與詞彙轉換（OpenCC s2t/t2s 詞典） | 地區用語屬強化項目，可在階段 7 評估 `tw2sp` |
| 23 | 介面風格 | **已決定並完成（2026-11-01）：改為 Bootstrap 5.3.8 風格** | 使用者指定。Bootstrap 檔案下載後放在本站 `assets/vendor/`，不從 CDN 載入，以符合 CSP `'self'` 限制；不使用 inline script |
| 24 | 隨手記附件的儲存位置 | **待決定**。建議：程式同時支援本機與 S3 相容儲存；正式使用採 Cloudflare R2（或改用付費主機） | InfinityFree 條款禁止把主機當檔案／媒體儲存，且單檔 10 MB、檔案數約 30,000；見 08 文件第 2 節 |
| 25 | 外部儲存的存取方式 | 經 PHP 代理（每次請求都做雙重授權） | 才能符合「撤銷權限後立即停止存取」；簽名網址在有效期內仍可使用 |
| 26 | 惡意檔案掃描 | 預設不啟用外部掃描服務 | 主機無法執行掃毒程式；外部服務會把公司檔案送到第三方。改以白名單、MIME 偵測、圖片重新編碼、不可執行、強制下載防護 |
| 27 | 圖片顯示位置 | 依上傳順序顯示在隨手記文字下方 | 與規格範例一致；不在文字中間插圖，以降低編輯器複雜度 |
