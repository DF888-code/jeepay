# 05 分階段開發計畫

每個階段完成時都必須提交：測試結果、權限檢查結果、資料庫結構變更說明、文件更新、已知限制。
未通過測試不得進入下一階段；不得以前端隱藏取代後端權限。

## 建議調整：TOTP 與救援 Email 的前後順序

第 3 階段（2FA）上線後，最高權限管理者若在第 10 階段前遺失驗證器將無法自救。
建議：開發與測試期間保留一個**僅限本機 CLI 執行**的緊急重設指令（不經網頁、需伺服器檔案存取權限），並在第 10 階段完成後評估是否保留。
此指令不會部署到 InfinityFree 的公開目錄。

## 首次安裝流程（規劃）

InfinityFree 無 SSH，因此提供 `install.php`：

1. 檢查 `config/config.php` 是否存在且金鑰長度正確；
2. 檢查資料庫是否為空；**若已有資料表則拒絕執行**（不覆蓋、不刪除任何資料）；
3. 建立資料表與第一位最高權限管理者（帳號、密碼、Email），強制下次登入綁定 2FA；
4. 完成後產生 `storage/installed.lock`，之後安裝頁永久停用；並提示刪除 `install.php`。

後續 Schema 變更透過 `database/migrations/` 依序執行，由最高權限管理者在後台觸發，只允許「新增」型遷移；
任何會刪除或改變既有資料的遷移，必須先提出並取得同意。

## 每階段的固定檢查

- [ ] 單元測試、整合測試（真實 MariaDB）全部通過
- [ ] 新增端點皆有「無權限」測試
- [ ] 新增紀錄點確認不含密碼、驗證碼、Token、Secret、隨手記內文
- [ ] Schema 變更有遷移檔與文件
- [ ] 前一階段功能回歸測試通過
- [ ] 已知限制已寫入文件
