## 緊急重設：救援 Email 上線前

第 3 階段（2FA）上線後，最高權限管理者若在第 10 階段前遺失驗證器將無法自救。
原規劃為「本機 CLI 緊急指令」，但 InfinityFree 沒有命令列環境，因此改為透過主機控制台的 phpMyAdmin 執行一段 SQL，
步驟見 [07-deployment.md](07-deployment.md) 第 3 節。

## 首次安裝流程（已實作）

InfinityFree 無 SSH，因此以網頁 `/install` 安裝：

1. `config/config.php` 不存在或不完整時，顯示設定說明頁（並提供可複製的隨機 `app_key`、`install_token`）；
2. 必須輸入 `config.php` 中的 `install_token`，避免網站剛上線時被陌生人搶先建立管理者；
3. 建立資料表（執行 `database/migrations/`）與第一位最高權限管理者，強制登入後綁定 2FA；
4. 資料庫已有使用者時一律拒絕，**不覆蓋、不刪除任何資料**；
5. 完成後寫入 `storage/installed.lock`，安裝頁永久回應 404。

後續 Schema 變更透過 `database/migrations/` 依序執行，由最高權限管理者在後台觸發，只允許「新增」型遷移；
任何會刪除或改變既有資料的遷移，必須先提出並取得同意。

## 階段 3 報告：使用者登入及 2FA（2026-10-30）

### 完成內容

| 功能 | 說明 |
|---|---|
| 登入狀態機 | 未登入 → 密碼正確 → 待驗證碼／強制綁定 → 完整登入；未完成前其他頁面導回對應步驟、API 回 401／403 |
| TOTP | 自行實作 RFC 6238，與 Google Authenticator 相容；時間容許範圍可設定；同一組驗證碼不能重複使用（條件式 UPDATE 保證併發下只成功一次） |
| QR Code | 伺服器端產生 SVG，不呼叫外部服務；附手動輸入金鑰 |
| 2FA Secret 保存 | 以 `app_key` 衍生的子金鑰（libsodium secretbox）加密後存入資料庫 |
| 強制綁定 | 新帳號、被管理者重設 2FA 的帳號，密碼正確後只能進入綁定頁 |
| 個人帳號設定 | 查看 2FA 狀態；修改密碼（需目前密碼）；更換驗證器（需目前密碼 + 目前驗證碼 → 掃描新 QR → 新驗證碼確認才替換） |
| Session 安全 | HttpOnly、SameSite=Lax、HTTPS 時 Secure；登入各階段更換 Session ID；閒置與絕對逾時；Session 檔存於專案 storage |
| 立即失效 | 每個請求重新讀取使用者；停用帳號、修改密碼、更換或重設 2FA 時其他裝置立即登出 |
| 登入節流 | 依帳號（HMAC 雜湊，不存原文）與 IP 計算；密碼與驗證碼錯誤合併計算；只有完整登入成功才重置 |
| CSRF | 所有 POST 檢查同步 Token |
| 安全標頭 | CSP（禁止 inline script）、X-Frame-Options、nosniff、Referrer-Policy、HTTPS 時 HSTS、`Cache-Control: no-store` |
| 歷史操作紀錄 | 登入成功／失敗、登出、2FA 綁定、更換 2FA、修改密碼、安裝；不含任何機密 |
| 安裝流程與部署包 | `/install`、`tools/build-deploy.php` 產生可「Upload & Unzip」的 zip |

### 測試結果

執行 `php tests/run.php`（MariaDB 10.11、PHP 8.3）：

- 單元測試 10 項全部通過：RFC 6238 測試向量、時間容許範圍、防重放、Base32、加密與竄改偵測、密碼規則、設定驗證、遷移檔拆分；
- 整合測試 27 項全部通過（實際啟動網站、以 HTTP 操作）：安裝金鑰與 CSRF、安裝後停用、未登入／未綁定時的頁面與 API 阻擋、
  Session ID 更換、帳號列舉防護、QR Code 不外送、綁定與登入、防重放、帳號鎖定、
  「已知密碼反覆猜驗證碼」不會重置鎖定、修改密碼使其他裝置失效、更換 2FA 舊驗證器失效、停用帳號立即登出、
  管理者重設 2FA 後強制重新綁定、紀錄不含機密、節流表不存帳號原文、IP 鎖定；
- Schema 驗證測試 26 項全部通過；
- 連續執行 3 次結果一致；
- Playwright 截圖檢查 375px 手機與 1280px 桌機版面，手機無水平捲動；
- 部署包（142 個檔案、約 196 KB）在 Apache 2.4 上實測：私有目錄全部被拒絕存取，安裝與登入流程正常。

### 開發中發現並修正的問題

- 遷移檔拆分使用 `\R` 時，非 UTF-8 模式下會把中文字中的 `0x85` 位元組當成換行，導致 SQL 被切壞；已改為只以 `\n`／`\r` 切割並加上單元測試。
- 設計節流時發現：若「密碼正確」就重置失敗次數，已知密碼的攻擊者可以無限猜驗證碼；已改為只有完整登入成功才重置，並加入整合測試。

### 已知限制

- 開發環境為 PHP 8.3，正式主機為 PHP 8.4；程式未使用 8.4 已淘汰的語法，但仍需在主機上實際操作確認；
- `.htaccess` 的存取保護已在開發環境的 Apache 2.4 驗證通過，但仍需在 InfinityFree 上依 07 文件第 4 節再檢查一次；
- 管理者重設員工 2FA、停用帳號的**介面**屬於階段 4，本階段以資料庫操作驗證其效果；
- Email 救援屬於階段 10；在此之前的緊急處理方式見 07 文件第 3 節；
- 登入失敗以外的紀錄查詢介面屬於階段 8，本階段紀錄已寫入資料庫。
